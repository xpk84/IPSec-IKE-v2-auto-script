# IKEv2-server-autoscript — xpk84 fork (v2.3)

Форк [mikrotik-user/IPSec-IKE-v2-auto-script](https://github.com/mikrotik-user/IPSec-IKE-v2-auto-script)
(оригинал заморожен 13.01.2022, не обновлялся). Форк — хозяин кодового пути
выпуска/отзыва клиентских IKEv2-сертификатов.

## Отличия от оригинала (v2.3, 2026-10-23)

| Область | Оригинал | Форк |
|---|---|---|
| Имя скрипта | `IKEv2` | `IKEv2_run_to_create` |
| Пароль pkcs12 | ≥ 7 символов, печатается в консоль | ≥ 8 символов, **не печатается** (только длина) |
| Срок клиентского серта | всегда 365 (зашито в шаблоне) | спрашивается; **Enter = случайный 330–395 дней** (антикучность истечений) |
| DH-группы (новые инсталлы) | modp2048, modp1536, modp1024 | **только modp2048** |
| Proposal ESP | sha1, aes-192-* в наборах | **без sha1 и aes-192-*** (CBC 256/128 оставлены для совместимости с Windows) |
| Отзыв пира (меню 3) | revoke + identity (серт остаётся R-мусором) | **полный cleanup**: identity → revoke → remove серта → удаление p12 из Files → удаление rollback-скрипта |
| Rollback-скрипт пира | revoke + identity, живёт вечно | полный cleanup + **самоудаление** в конце |
| Промпты | без примеров, с опечатками | примеры/шаблоны в каждом вопросе (без реальных доменов/IP/имён — v2.3) |
| Заголовок скрипта | — | RUN-комментарий: только из терминала, кнопка Run в WinBox не работает |
| IKEv2-rollback | — | первая строка — WARNING о полном сносе IKEv2/L2TP-certs сервера |

Кодовый путь выпуска/отзыва не менялся: те же команды в том же порядке, то же интерактивное меню.

## Установка / обновление на роутере

```routeros
/system script remove [find name="IKEv2_run_to_create"]
/import IKEv2-server-autoscript.rsc
```

Файл положить в Files. Импорт пересоздаёт скрипт целиком.

## Порядок выдачи (меню 2 — Create peer)

1. Имя пира — конвенция: `ike2_<user>_<device>_<год>` (подсказка с живым годом — в промпте);
   сертификат получится `<peername>@<домен сервера>`.
2. Пароль pkcs12 — ≥ 8 символов (в консоль не выводится).
3. Срок сертификата в днях — Enter даст случайный из 330–395; после подписания печатается
   фактическая дата истечения (из самого сертификата).
4. `Continue? [y]` → сертификат подписан, p12 в Files, identity создан, rollback-скрипт сгенерирован.
5. p12 забрать из Files и поставить клиенту; гейт приёмки — клиент подключился и пингует офис через туннель.

## Отзыв (меню 3 — Revoke peer)

Ввести имя пира → скрипт удалит identity, отзовёт и удалит сертификат, вычистит p12-файлы
и уберёт rollback-скрипт пира. Хранилище сертификатов не обрастает отозванными записями.

## Запуск

Только из живой консоли (WinBox New Terminal или ssh): `/system script run IKEv2_run_to_create`.
Кнопка Run в WinBox падает с `missing value(s) of argument(s) value` — интерактивным промптам нужна консоль.

## Совместимость

- RouterOS 7.x. Проверено на 7.24.5.
- ⚠️ `:rnd` в RouterOS **не существует** (вопреки старым упоминаниям) — случайный срок
  генерируется из системных часов, см. v2.3.2.

## Импорт p12 на macOS (RouterOS 7.24+)

RouterOS (после обновления ~7.16–7.24) упаковывает приватный ключ в PKCS#12
по-новому: `PBES2 + PBKDF2 + AES-256-CBC`. macOS Keychain Access / `security import`
проверяют MAC по паролю (пароль «принимается»), но **молча выбрасывают PBES2-ключ** —
импортируется сертификат без ключа: identity не создаётся, Machine Certificate не выбирается.
Старые экспорты (до обновления, `pbeWithSHA1And3DES`) импортируются нормально.

Лечение — пересобрать p12 в legacy-шифрование и импортировать его:

```bash
openssl pkcs12 -in peer.p12 -out bundle.pem -nodes          # спросит пароль p12
openssl pkcs12 -export -legacy -in bundle.pem -inkey bundle.pem \
  -name "peer@host" -out peer.legacy.p12                    # спросит/возьмёт пароль
rm bundle.pem
sudo security import peer.legacy.p12 -k /Library/Keychains/System.keychain -A
security find-identity -v /Library/Keychains/System.keychain  # должна появиться identity
```

Готовый helper — `tools/vpn-import-mac.sh`: скачивает p12 с роутера по scp,
пересобирает, чистит дубли, импортирует identity и проверяет её — одной командой.
Пример конфига — `tools/vpn-import-mac.conf.example`.

(`-A` — разрешить VPN-демону доступ к ключу без GUI-промптов; если `-legacy` нет в вашей
сборке openssl — замените на `-certpbe PBE-SHA1-3DES -keypbe PBE-SHA1-3DES -macalg sha1`.
CA сертификат ставится в System keychain отдельно, как обычно.)

## Согласование порядков в rollback

`arrayRollback` собирается в обратном порядке (`:for x from=[:len ...] to=0 step=-1`),
поэтому дополненные appends (self-remove, files, cert-remove) вставлены **до** базовых
(revoke, identity) — в итоговом скрипте порядок исполнения:
`identity → revoke → cert remove → files → самоудаление`.

## RouterOS-инженерия (выяснено на живом железе 7.24.5)

- Интерполяция `$var` внутри строки-аргумента вызова `[$func "..."]` — **синтаксическая ошибка**
  парсера (в выражениях `("...")` — работает). Поэтому все подсказки с переменными собраны конкатенацией.
- Date-math отсутствует: `:todate` не существует, `[:totime]`+дни даёт длительность, не дату.
  Дата истечения печатается из `invalid-after` подписанного сертификата.
